# Attendance Correction Portal

HR uploads the monthly attendance workbook downloaded from SAP. The portal does the job the Excel
macro used to do. It calculates every day from the `SAP` sheet and fills the `TO CONSIDER` sheet.
It then emails each manager a link, and managers correct their own team's days. HR downloads the
finished workbook.

- **No AI.** The status rules are a direct translation of the macro formula (`app/core/rules.py`).
- **Checked against the real October 2026 workbook.** All 2,880 employee-days match the macro. On an
  empty upload, the downloaded file is identical to the macro's output, cell by cell. See `DECISIONS.md`.

## How it works

1. **Upload** (HR): `.xlsm` / `.xlsx`, up to 25 MB, with an optional correction deadline. The portal reads
   `TO CONSIDER` and `SAP` only. It never loads `HC_Teamlease`.
2. **Review** (HR): summary, exceptions (CSV download), managers with email status and number of changes.
3. **Email**: one email per manager with the team size and a link. No employee data goes in the email.
4. **Correct** (manager): the manager signs in with their Microsoft work account and sees only employees whose
   `Manager Email` is theirs. They change days and click **Save**. Every change goes into an append-only audit log.
5. **Download** (HR): the original file with the macro's work done:
   - the day values are written into `TO CONSIDER`,
   - empty total cells get the `COUNTIF`/`SUM` formulas,
   - empty SAP `Remarks` / `Remarks Code` cells get the macro's formulas.

   Only those cells change. The VBA project, the other sheets and the formatting stay byte-for-byte identical.
6. **Lock** (HR) when corrections are closed.

| Rule | Detail |
|---|---|
| 5DAG / 6DAG | P if worked ≥ 5:00:00, else A |
| OFF | P if worked ≥ 8:00:00, else OFF |
| PH | P if worked ≥ 5:00:00, else PH |
| other schedule | `?`, reported as an exception and never written to the workbook |

## Local development

Requires Python 3.11+.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
cp .env.example .env          # then edit: set HR_ADMIN_EMAILS to your test email
```

Pick a database:

- **Quickest (no Docker):** set `MONGODB_URI=mongomock://` in `.env`. This is an in-memory database and the data is
  lost on restart. The app refuses this in production.
- **Real MongoDB:** run `docker compose up -d` and keep `MONGODB_URI=mongodb://localhost:27017`.

Run the app:

```bash
.venv/bin/uvicorn app.main:app --reload
```

Open http://localhost:8000. With `DEV_LOGIN=true` you can sign in as any email:
- an email listed in `HR_ADMIN_EMAILS` gets the HR screens,
- a `Manager Email` from the workbook gets that manager's team.

Emails are printed to the console (`EMAIL_MODE=console`).

### Tests

```bash
.venv/bin/python -m pytest -q
```

The tests need no network and no MongoDB: they use `mongomock`, and the Graph and Entra calls are mocked.
They use only fake workbooks generated by `tests/fixtures/make_sample_workbook.py`. **Never commit real
workbooks**: `.gitignore` blocks `*.xlsm`, `*.xlsx` and `*.csv`.

### Checking against a real workbook (local only)

```bash
# 1. The rules match the macro: recalculates every day from SAP and compares with TO CONSIDER.
.venv/bin/python -m scripts.verify_against_macro "path/to/Attendance.xlsm"

# 2. Side by side: clears what the macro fills, runs the app, and compares the result with the macro's file.
.venv/bin/python -m scripts.side_by_side "path/to/Attendance.xlsm" --save-dir /some/private/folder
```

Run both on a workbook where the macro **has already run**. Exit code 0 means identical. They print employee IDs
and dates only, never names. Use `--save-dir` to keep the cleared upload and the app's output so you can open them
in Excel.

## Configuration

All settings are environment variables (see `.env.example`). In Azure, set them under **App Service → Settings →
Environment variables**.

| Variable | Default | Notes |
|---|---|---|
| `ENV` | `development` | `production` turns on strict startup checks and Secure cookies |
| `APP_BASE_URL` | `http://localhost:8000` | Public URL, used in emails and the login redirect. `https://` in production |
| `SECRET_KEY` | — | Signs the session cookie. At least 32 random characters in production |
| `MONGODB_URI` / `MONGODB_DB` | local / `attendance` | Cosmos DB connection string (see below) |
| `DEV_LOGIN` | `false` | Email-only login for development. **The app refuses to start if this is true in production** |
| `HR_ADMIN_EMAILS` | — | Comma-separated HR emails |
| `ENTRA_TENANT_ID` / `ENTRA_CLIENT_ID` / `ENTRA_CLIENT_SECRET` | — | App registration |
| `EMAIL_MODE` | `console` | `graph` to send real email |
| `SENDER_MAILBOX` | — | Mailbox the emails are sent from |
| `EMAIL_CC` | — | Optional CC, comma-separated |
| `EMAIL_PER_SECOND` | `2` | Throttle for Graph |
| `WORKDAY_MIN_HOURS` / `OFFDAY_MIN_HOURS` / `PH_MIN_HOURS` | 5 / 8 / 5 | Rule thresholds |
| `ALLOWED_STATUSES` | `P,A,OFF,PH,CO,ML,PL` | The codes the totals formulas count |
| `GRID_SOURCE` | `to_consider` | `to_consider` keeps values already in the sheet; `sap` prefers the SAP calculation |
| `TIMEZONE` | `Asia/Kolkata` | For deadlines and timestamps |
| `MAX_UPLOAD_MB` | `25` | |
| `SESSION_HOURS` | `8` | Sessions end this long after sign-in |

## Azure deployment

### 1. Entra ID app registration (one registration for login and email)

1. Go to **Entra admin centre → App registrations → New registration**.
   - Name: `Attendance Portal`. Supported accounts: *this organisational directory only*.
   - Redirect URI: platform **Web**, `https://<your-app>.azurewebsites.net/auth/callback`
     (for local testing also add `http://localhost:8000/auth/callback`).
2. **Certificates & secrets → New client secret.** Copy the value into `ENTRA_CLIENT_SECRET`. Note the expiry date
   and renew it before it expires.
3. **API permissions → Add → Microsoft Graph:**
   - *Delegated*: `openid`, `profile`, `email`, `User.Read` (for sign-in).
   - *Application*: `Mail.Send` (for the manager emails).
   - Click **Grant admin consent**.
4. Copy the **Directory (tenant) ID** and **Application (client) ID** into `ENTRA_TENANT_ID` and `ENTRA_CLIENT_ID`.
5. **Important: restrict `Mail.Send` to the sender mailbox.** The application permission otherwise allows sending as
   *any* mailbox in the tenant. An Exchange admin should limit it, using RBAC for Applications (recommended) or the
   older application access policy:

   ```powershell
   # RBAC for Applications
   New-ServicePrincipal -AppId <client-id> -ObjectId <enterprise-app-object-id> -DisplayName "Attendance Portal"
   New-ManagementScope -Name "Attendance sender" -RecipientRestrictionFilter "PrimarySmtpAddress -eq 'hr.attendance@company.com'"
   New-ManagementRoleAssignment -App <client-id> -Role "Application Mail.Send" -CustomResourceScope "Attendance sender"
   ```

   Or, with an application access policy:

   ```powershell
   New-ApplicationAccessPolicy -AppId <client-id> -PolicyScopeGroupId hr.attendance@company.com -AccessRight RestrictAccess -Description "Attendance portal sender only"
   ```

   If you use RBAC for Applications, remove the tenant-wide `Mail.Send` consent afterwards, so only the scoped role
   assignment grants access.

### 2. Azure Cosmos DB for MongoDB (RU)

1. Create **Azure Cosmos DB for MongoDB** (request unit model), server version 4.2 or later.
2. Copy the primary connection string into `MONGODB_URI`. It **must** contain `retrywrites=false`; add it if missing:
   `mongodb://<account>:<key>@<account>.mongo.cosmos.azure.com:10255/?ssl=true&replicaSet=globaldb&retrywrites=false&maxIdleTimeMS=120000&appName=@<account>@`
3. The app creates its collections and indexes at startup. Uploaded workbooks are stored in GridFS (`files.*`
   collections). If GridFS causes problems on your Cosmos tier, add a Blob Storage `FileStore`
   (see `app/db/file_store.py`).
4. Turn on **continuous backup** for point-in-time restore.

### 3. App Service (Linux, Python 3.11 or 3.12)

1. Create a **Web App**: Publish *Code*, Runtime *Python 3.12*, OS *Linux*. B1 or larger is enough.
2. **Configuration → General settings:**
   - Startup command: `gunicorn -w 2 -k uvicorn.workers.UvicornWorker app.main:app --timeout 300 --bind 0.0.0.0:8000`
   - HTTPS only: **On**. Minimum TLS: 1.2.
3. **Environment variables:** set everything from the table above, with `ENV=production`, `DEV_LOGIN=false`,
   `EMAIL_MODE=graph`, and a long random `SECRET_KEY`, for example from `python -c "import secrets; print(secrets.token_urlsafe(48))"`.
   Better still, keep the secrets in **Key Vault references**.
4. Also set `SCM_DO_BUILD_DURING_DEPLOYMENT=true`, so App Service installs `requirements.txt` on deploy.
5. Deploy, for example with `az webapp up`, GitHub Actions, or a zip deploy of the repo. Do not include `.env` or any
   workbook.
6. **Health check:** set the path to `/healthz`. It returns 200 when the database is reachable.

If the settings are wrong for production (for example, dev login on or a weak secret), the app refuses to start
and logs the reason. Check **Log stream**.

## Security notes

- Every request is checked on the server:
  - managers can read and change only their own team,
  - all edits are validated against `ALLOWED_STATUSES` and the cycle's dates,
  - a save is all-or-nothing.
- Sessions use a signed cookie: HttpOnly, SameSite=Lax, Secure in production. A session lasts at most 8 hours
  from sign-in.
- All POST requests need a CSRF token. The app also sends security headers (CSP, X-Frame-Options, HSTS in
  production).
- Logs contain IDs and counts only, never employee names or emails. The one exception is the console email sender,
  which is development only.
- Two people editing the same day at once: the second save is reported as a conflict rather than silently
  overwriting the first.
- CSV exports protect against spreadsheet formula injection.

## Code map

| Path | What it does |
|---|---|
| `app/core/rules.py` | `to_seconds`, `calculate_status`: the macro rules |
| `app/core/workbook_reader.py` | Reads `TO CONSIDER` and `SAP`, detects dates, totals and SAP columns |
| `app/core/grid.py` | Grid (`days`, `original_days`, `sheet_days`, `calculated_days`) and the exceptions report |
| `app/core/processing.py` | Upload pipeline with rollback |
| `app/core/editing.py` | Permission rules and saving edits with the audit log |
| `app/core/workbook_writer.py` | Builds the download: days, totals formulas and SAP formulas |
| `app/core/xlsx_patch.py` | Edits individual cells in the workbook XML; everything else is copied unchanged |
| `app/db/` | MongoDB connection, repositories, `FileStore` (GridFS) |
| `app/email/` | Console and Graph senders, email template |
| `app/auth/` | Session, CSRF, Entra ID login |
| `app/routes/` | HR, team, API and auth routes |
| `scripts/` | `verify_against_macro.py`, `side_by_side.py` |
